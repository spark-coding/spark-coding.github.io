What a Lesson Looks Like

A 45-minute lesson with a maximum of three students. At least half of every lesson is your child at the keyboard making something, not watching.

1

One new idea

Never two at once. The first exercise is so easy that every child gets it right. Confidence first.

2

Small steps up

We add one small thing at a time, so kids can see themselves getting better as they go.

3

Make it yours

The main event. Each child builds their own version, such as a game or a handy tool. This is where most of the lesson goes.

4

Stretch or practise

Fast finishers get a harder challenge on the same idea. Others get another easy step. No one is rushed or held back.

How Much Can They Learn in a Term?

A term is about 10 weekly lessons. Where your child starts depends on what they already know, not just their age. Older beginners don't restart from blocks. Here's what one term looks like at each stage.

Stage 1

First code

Scratch · usually Year 3

By the end of the term they can:

  • Make things happen in order and on cue
  • Make characters talk to each other
  • Use randomness and if/else to make games unpredictable
  • Store and use items in a list

Builds like: Whack-a-Mole, Tap Piano, and a finished game for their portfolio.

Stage 2

Blocks to real code

MakeCode Arcade · usually Years 3–4

By the end of the term they can:

  • Build arcade games with blocks
  • Flip to the Python view and edit real code
  • Use variables, true/false and functions
  • Ship a game to their portfolio

Builds like: Catch the Falling Items, Space Shooter, playable on a micro:bit console.

Stage 3

Python

Python · usually Years 4–6

By the end of the term they can:

  • Write Python from a blank file without fear
  • Use variables, input and if/elif/else
  • Read an error message calmly and fix it
  • Start using loops and lists

Builds like: a trading card maker, a calculator and a quiz.

Stage 4

Building skills

Python · usually Year 7+

By the end of the term they can:

  • Work with grids, records and files
  • Search and sort, and count the steps
  • Plan with pseudocode and test cases
  • Prepare for coding competitions (optional)

Builds like: Secret Codes, a leaderboard, and Spark Arena bots.

After one term

They'll show you a program they built themselves. You'll hear them ask, "What if I made it do this instead?"

After one year

They'll fix their own bugs without asking, and have made something they're genuinely proud of.

After three years

They'll read and write the same kind of code professional programmers use, and have at least one competition certificate.

We go deep, not fast: most children spend one to two years at each stage, practising each idea until it feels easy.
